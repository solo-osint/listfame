# Выгрузка участников Telegram

Русскоязычный публичный бот. Каждый человек обращается к боту в личке, добавляет его администратором своего чата и выбирает группу/канал. Проверяется админство и пользователя, и бота в выбранном чате. Повторная проверка выполняется после очереди, перед отправкой файлов и при каждом запросе страницы текста. При ошибке проверки данные не раскрываются.

## Запуск в Windows

Нужен установленный Python 3.11 или новее (проверено на Python 3.14.7).

1. Распакуйте архив в отдельную папку.
2. Скопируйте `.env.example` в `.env` и заполните `BOT_TOKEN`, `API_ID`, `API_HASH`. В рабочей папке автора `.env` уже заполнен; архив секретов не содержит.
3. API ID и API Hash получают в разделе API development tools на https://my.telegram.org. Это данные приложения; вход в аккаунт пользователя и userbot для работы не используются.
4. Откройте PowerShell в папке проекта:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe bot.py --check
.\.venv\Scripts\python.exe -u bot.py
```

Либо запустите `start.ps1` через PowerShell. Окно/процесс и компьютер должны оставаться включёнными, нужен доступ к Telegram. Для остановки в открытом окне — Ctrl+C. Для фонового запуска используется отдельный скрытый процесс; его PID хранится в `work/bot.pid`, а служебный вывод — в `work/bot.stdout.log`. Завершайте только этот конкретный процесс, проверив его командную строку. Автозапуск после перезагрузки не установлен, платный хостинг не подключён.

Одновременно запускайте только один экземпляр. Если установлен webhook, программа остановится и не удалит его. При конфликте getUpdates (409) программа также остановится. Сессия MTProto должна принадлежать тому же боту; это проверяется перед приёмом заявок. Секреты и сессия находятся в `.env` и `work/`, не передавайте их вместе с исходниками.

## Использование

Откройте личку бота, нажмите Start. Добавьте бота администратором своего чата, затем используйте «Выбрать группу» / «Выбрать канал». Если Telegram-клиент не поддерживает кнопки, отправьте @username, публичную ссылку вида https://t.me/username или отрицательный ID чата (для супергрупп/каналов обычно -100…). Приватные пригласительные ссылки не принимаются: для приватного чата используйте кнопку или ID. При отсутствии прав выдача запрещена. После ссылки бот спрашивает: выгрузка без фильтра или по эмодзи в нике. С фильтром в ответ приходит список «ник - должность» только для тех, у кого этот знак есть в имени, а последним сообщением — сколько человек с флагом и сколько без.

В ответ придут `.xlsx` и `.txt` с полями: имя, username, числовой Telegram ID, owner/admin/member, видимая подпись. Excel хранит все поля как текст, в том числе ID и строки, начинающиеся с `=`: формулы из имён не выполняются. Текст можно получить по кнопке порциями, без скачивания файла. `/cancel` отменяет очередь/сбор и удаляет сохранённый текст; `/delete` делает то же. Уже отправленные Telegram-файлы и сообщения эти команды не удаляют.

## Границы результата

Обычный HTTP Bot API не перечисляет всех участников. Здесь он используется для интерфейса, проверки прав, счётчиков и администраторов; сбор выполняется через MTProto **с авторизацией бота**. Для супергрупп/каналов используется постраничный `channels.getParticipants` с фильтром Recent, без обхода скрытых списков и без сбора авторов сообщений. Для обычных групп используется `messages.getFullChat`.

Telegram может ограничить выдачу, вернуть лишь часть списка, скрыть участников или запретить метод для конкретного чата. Приватные каналы адресуются InputChannel с bot access_hash=0; если Telegram отклонит адресацию/доступ, результат явно помечается частичным, без обхода прав. Администраторы дополнительно получаются через Bot API. `rank` из MTProto (включая доступный member tag) и `custom_title` из Bot API сохраняются, когда Telegram их возвращает. Отсутствующая подпись не доказывает, что её нет в приложении. При неподдерживаемом поле требуется обновление библиотеки/схемы.

В каждом результате: получено N, общий счётчик до/после, причина остановки. Даже равенство N и счётчика не объявляется доказательством полноты: состав может меняться во время сбора. Все результаты обозначены как потенциально частичные. Дедупликация — по Telegram ID. На FloodWait выдаётся накопленная часть и требуемая пауза. Повторный запрос этого же чата до конца паузы отклоняется сообщением «ещё N секунд»; автоматического повтора нет. Пока идёт постраничный сбор, бот изредка пишет «Получено N» — только число, без списка.

По умолчанию сбор ограничен 240 секундами и 100000 участников. `EXPORT_TIMEOUT` ограничен сверху 270 секундами. Это время сбора: очередь, сетевые проверки и отправка файлов добавляют время, гарантии пяти минут нет. Один активный сбор, до 10 заявок включая активную, одна заявка на пользователя. При перезапуске очередь и кеш теряются. Это локальный однопроцессный вариант; для большой публичной нагрузки потребуется отдельная эксплуатационная настройка.

Временные файлы создаются только на время отправки и удаляются при успехе/ошибке/обычной отмене. Текст хранится в памяти до 10 минут (периодическая очистка каждые 5 секунд), максимум для 20 пользователей; Telegram продолжает хранить уже отправленные сообщения и документы. При аварийном завершении процесса временные файлы ОС могут остаться в системной временной папке. В логах не печатаются токен, API Hash, списки участников и полные сетевые исключения. Не включайте отладочное логирование HTTP.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest -v
```

Тесты проверяют отказ при недостаточных/отозванных правах, изоляцию текстовых результатов пользователей, дедупликацию, сохранение частичного результата при таймауте/FloodWait, отмену, удаление временных файлов, Unicode-порции текста, member tag и защиту Excel от формул. Интеграционная выгрузка из реальной группы требует добавления бота пользователем; её нельзя заменить синтетическим тестом.
